Article I — Product Definition

A governance compiler,
not a document.

The Living Constitution is not a policy document, a prompt wrapper, or a runtime filter. It is an executable governance operating system — the only system in the field that governs its own development under the same invariants it enforces on external agents.

The Living Constitution is a governance operating system and development overlay for frontier coding agents and AI product teams. It wraps Claude Code, Codex, and Gemini with constitutional constraints, evidence capture, invariant enforcement, and dual-topology product governance.

The Load-Bearing Insight

A constitution defines a type system for power — who can do what, under what constraints, with what evidence, through what amendment process. TLC makes that type system executable. The C-RSP series structure (A–E) completes the compiler: Series A gives it a formal grammar, Series B a linker and symbol table, Series C a runtime, Series D a standard library, Series E an IDE.

Structural Principle

TLC is self-hosting. Every series adds capability to the governance system and immediately subjects that new capability to the governance system it just extended. This recursive self-application is what makes TLC a living constitution rather than a dead document — and what makes the product positioning credible.

Article VI — Guardian Mode Specification

The enforcement
runtime.

Guardian mode is TLC's active enforcement layer — the runtime that intercepts agent actions before execution. It resolves the Critical failure E1 from the stakeholder review by specifying the exact interception mechanism: Linear Context Injection at the system-prompt level, not git hooks.

Interception Architecture
Critical Resolution — E1

Pre-commit hooks check committed code, not agent actions in flight. Guardian mode intercepts at the system-prompt level via Linear Context Injection (LCI) — inserting invariant checks into the agent's context before any tool call executes. For Claude Code: CLAUDE.md constitutional preamble + LCI. For MCP-based agents: MCP server wrapping the tool-call layer. For standalone agents: guardian.py check(action, context) gate before execution.

// packages/tlc-guardian/guardian.py — MVP implementation // Single file. Hexagonal core from sentinelos. Loads invariant-registry.json. import json, hashlib, datetime class Guardian: def __init__(self, config_path: str): """Load invariants from registry. Hash config for tamper detection.""" self.config = json.load(open(config_path)) self.config_hash = hashlib.sha256( open(config_path, 'rb').read() ).hexdigest() self._verify_config_integrity() def check(self, action: dict, context: dict) → dict: """ Returns: {allow: bool, evidence: Record, violations: list} Evidence record is SHA-256 anchored and exportable. """ violations = self._evaluate_invariants(action, context) evidence = self._build_evidence_record(action, context, violations) return { "allow": len(violations) == 0, "evidence": evidence, "violations": violations } def _verify_config_integrity(self): """INVARIANT_03: Guardian verifies its own config before enforcing.""" current = hashlib.sha256( open(self.config_path, 'rb').read() ).hexdigest() if current != self.config_hash: raise GuardianConfigTamperError("Config modified after load")

Anthropic's April 2, 2026 research confirmed that functional desperation vectors causally increase misaligned behavior (blackmail, reward hacking) even with no overt emotional markers in output. Guardian mode operationalizes this finding as an early-warning monitoring layer — the first governance system to do so.

This operationalizes Anthropic's recommendation that "measuring emotion vector activation could serve as an early warning that the model is poised to express misaligned behavior."
